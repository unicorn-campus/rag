# 역량 질문(Competency Question) 만드는 법: Ontology 101 기준  

## 0. 개요  

- 역량 질문: 지식 구조(온톨로지, 그래프 스키마)로 만든 지식 기반이 **답할 수 있어야 하는 질문 목록**  
- 근거 자료: Natalya F. Noy, Deborah L. McGuinness, 「Ontology Development 101: A Guide to Creating Your First Ontology」,  
  Stanford University. https://protege.stanford.edu/publications/ontology_development/ontology101-noy-mcguinness.html  
- 개념의 원출처: Gruninger, M., Fox, M.S.(1995). Methodology for the Design and Evaluation of Ontologies.  
  IJCAI-95 Workshop on Basic Ontological Issues in Knowledge Sharing(Ontology 101 참고문헌에서 인용)  
- 문서 구성: 1 ~ 4절은 Ontology 101에 적힌 내용을 쉬운 말로 옮긴 것, 5절은 그 내용을 실무에 쓸 때의 일반 권고  
  (Ontology 101에는 없는 내용이라 따로 구분함)  

## 1. 역량 질문이 하는 일  

Ontology 101은 역량 질문을 온톨로지 개발 첫 단계(Step 1. 도메인과 범위 정하기)에 둠. 하는 일은 두 가지임.  

| 쓰임 | 뜻 |
|---|---|
| 범위 정하기 | 질문에 답하는 데 필요한 개념은 넣고, 관련은 있어도 질문에 안 쓰이는 개념은 뺌 |
| 나중의 시금석(litmus test) | 완성한 온톨로지가 그 질문에 답할 만큼 정보를 담았는지, 답에 필요한 상세 수준을 갖췄는지 확인 |

- 역량 질문은 **초안(sketch)이면 충분하고 빠짐없을 필요는 없음**이라고 명시함  
- 질문에 대한 답(정답)을 함께 쓰라고 하지 않음. 질문 목록만으로 범위와 시금석 역할을 함  

## 2. 역량 질문 앞에 답할 기본 질문 4가지  

Step 1은 역량 질문을 쓰기 전에 아래 4가지에 먼저 답하라고 권함.  
답은 설계 중에 바뀔 수 있지만, 그때그때 모델의 범위를 좁히는 데 씀.  

1. 온톨로지가 다룰 **도메인**은 무엇인가  
2. 온톨로지를 **어디에 쓰려는가**(용도)  
3. 온톨로지의 정보가 **어떤 유형의 질문에 답해야 하는가** → 역량 질문으로 구체화  
4. **누가 쓰고 누가 관리하는가**  

용도와 사용자에 따라 담을 정보가 달라지는 예(원문의 와인과 음식 예를 요약함)  

| 용도나 사용자 | 더 담아야 할 정보 |
|---|---|
| 와인 잡지 기사를 자연어 처리하는 데 씀 | 개념의 동의어와 품사 정보 |
| 식당 손님이 와인을 고르도록 도움 | 소매 가격 |
| 와인 구매 담당자가 창고를 채움 | 도매 가격과 재고 |
| 관리하는 사람과 쓰는 사람의 용어가 다름 | 두 용어 사이의 대응 |

- 범위 밖 예: 와이너리 재고 관리, 식당 직원 관리는 와인, 음식과 관련은 있지만 와인과 음식 조합 추천이라는 용도에는 넣지 않음  

## 3. 만드는 순서  

Ontology 101은 Step 1 안에서 서술형으로 설명함. 아래 순서는 그 설명을 단계로 정리한 것임.  

1. 2절의 기본 질문 4가지에 답해 용도와 사용자를 정함  
2. 그 사용자가 지식 기반에 물을 질문을 **초안으로 나열**함(빠짐없을 필요 없음)  
3. 질문 목록을 보고 **담아야 할 정보 묶음**을 뽑음  
4. 이후 단계에서 질문을 다시 씀  
   - Step 5(속성 정하기): 클래스만으로는 Step 1의 역량 질문에 답할 수 없으므로 개념의 내부 구조(속성)를 정함  
   - 개체(instance) 수준 정하기: 역량 질문의 답이 되는 가장 구체적인 개념이 지식 기반의 개체 후보가 됨  
5. 마지막에 시금석으로 씀: 질문에 답할 정보가 있는가, 답에 필요한 상세 수준인가  

## 4. 예시: 와인과 음식(원문 예를 옮김)  

원문은 와인과 음식 조합을 추천하는 온톨로지에 역량 질문 7개를 듦. 그중 일부를 우리말로 옮기면 다음과 같음.  

- 와인을 고를 때 어떤 특성을 봐야 하나?  
- 보르도는 레드 와인인가, 화이트 와인인가?  
- 카베르네 소비뇽은 해산물과 잘 어울리나?  
- 구운 고기에는 어떤 와인이 가장 좋은가?  
- (그 밖에 와인의 어떤 특성이 요리와의 어울림에 영향을 주는지, 빈티지 연도에 따라 맛이 바뀌는지 등)  

원문은 이 질문 목록에서 담아야 할 정보를 아래처럼 읽어 냄.  

- 여러 와인 특성과 와인 종류  
- 좋은 빈티지 연도와 나쁜 빈티지 연도  
- 와인 선택에 영향을 주는 음식 분류  
- 추천하는 와인과 음식 조합  

질문 하나가 곧 타입 하나가 되는 것이 아니라, **여러 질문을 함께 보고 필요한 정보 묶음을 정한다**는 점이 핵심임.  

## 5. 실무에 쓸 때의 일반 권고  

Ontology 101에는 없는 내용임. 1 ~ 4절을 실제 설계에 적용할 때 지키면 좋은 점을 정리함.  

### 5.1 질문은 실제 사용자 질문에서 가져옴  

- 2절의 "누가 쓰는가"에 해당하는 사람이 실제로 묻는 질문에서 출발함. 문서만 보고 지어낸 질문은 범위를 넓히거나 빠뜨리기 쉬움  
- 가져올 곳: 요구사항이나 사용자 스토리, 평가용 질문셋, 운영 중이면 질의 기록, 업무 담당자 인터뷰  

### 5.2 개수는 질문 유형의 수로 정함  

- Ontology 101에는 개수 기준이 없음. 정해 둔 숫자 대신 **사용자 질문 유형마다 1개 이상**을 씀  
- 질문 유형 뽑는 법  
  1. 실제 질문을 모음  
  2. 사람 이름, 상품 이름, 날짜, 금액 같은 구체적인 값을 빈칸으로 바꿈  
  3. 틀이 같은 것끼리 묶음. 묶음 하나가 질문 유형 하나임  
- 예: "카베르네 소비뇽은 해산물과 잘 어울리나?"와 "피노 누아는 치즈와 잘 어울리나?"는 같은 유형  
  ("{와인}은 {음식}과 잘 어울리나?")  
- 질문이 많으면 문서 종류나 업무 영역별로 나눠 관리함  

### 5.3 답이 될 이름은 질문에 미리 쓰지 않음  

- 역량 질문은 "무엇에 답해야 하나"를 정하는 단계이고, "어떤 클래스나 타입으로 담을지"는 그다음에 정함  
- 질문에 클래스나 타입 이름을 미리 쓰면 설계를 정해 놓고 질문을 쓰는 셈이 되어 범위 판단이 흐려짐.  
  LLM으로 후보를 뽑을 때는 주어진 이름만 따라 써서 다른 후보가 보이지 않음  
  - 피함: "WinePairing 노드의 score는 얼마인가?"  
  - 권함: "구운 고기에는 어떤 와인이 가장 좋은가?"  
- 질문 하나에는 한 가지만 물음. 이유를 함께 묻는 질문은 "무엇을, 왜"처럼 같이 써도 됨  

### 5.4 시금석으로 쓰려면 기대 답을 따로 준비함  

- 역량 질문 자체는 질문만 있으면 됨(1절)  
- 완성한 스키마가 질문에 답하는지 숫자로 확인하려면 **표본 문서 몇 건의 기대 답**을 별도 시험 자료로 준비함  
  - 질문마다 "이 문서에서 답은 무엇이고 어디에 있나"를 적음  
  - **답이 없어야 하는 문서도 넣음**. 없는 것을 잘못 만들어 내는 오류는 이런 문서로만 찾을 수 있음  
- 질문을 질의어(SPARQL, Cypher 등)로 바꿔 두면 지식 기반에 돌려 기대 답이 나오는지 자동으로 시험할 수 있음  

### 5.5 역량 질문 초안을 LLM에게 요청하는 프롬프트 예  

```text
[목표]
지식 구조의 범위를 정하기 위하여, 아래 사용자 질문과 표본 문서를 보고 역량 질문 목록 작성

[처리]
1. 사용자 질문에서 사람 이름, 상품 이름, 날짜, 금액 같은 값을 빈칸으로 바꾸고 틀이 같은 것끼리 묶음
2. 묶음마다 역량 질문을 1개 이상 씀. 표본 문서에 답이 있는 질문만 남김
3. 클래스나 타입 이름은 쓰지 않고 질문 문장으로만 씀

[출력]
- 표: 질문 유형, 역량 질문, 근거가 된 사용자 질문, 표본 문서에서 답이 있는 위치

<사용자질문>
{요구사항, 사용자 스토리, 평가용 질문}
</사용자질문>
<표본문서>
{문서 종류별 표본 몇 건}
</표본문서>
```

- LLM이 만든 목록은 초안임. 사람이 용도와 사용자(2절)에 비춰 빼고 보탠 뒤 확정함  

## 6. 점검 체크리스트  

- [ ] 도메인, 용도, 답할 질문 유형, 사용자와 관리자 4가지에 답했는가  
- [ ] 질문이 실제 사용자 질문에서 나왔는가  
- [ ] 사용자 질문 유형마다 역량 질문이 1개 이상 있는가  
- [ ] 질문에 답이 될 클래스나 타입 이름을 미리 쓰지 않았는가  
- [ ] 질문에 쓰이지 않는 개념을 범위 밖으로 뺐는가  
- [ ] 시험용으로 표본 몇 건의 기대 답과 답이 없어야 하는 문서를 따로 준비했는가  
- [ ] 완성한 지식 구조가 각 질문에 답할 수 있는지(시금석) 확인했는가
