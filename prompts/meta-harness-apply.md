[목표]
- 기존 AI 에이전트의 하네스를 Meta-Harness 방식으로 한 단계 발전
- 모델은 고정, 하네스 코드만 변경. 제안자가 보지 않은 질문(holdout)에서 정확도·비용 개선 확인

[역할]
- 당신은 하네스 엔지니어임. 제안자(코딩 에이전트)가 도는 바깥 루프의 설계·구현·실행 담당

[맥락]
- Meta-Harness: 코딩 에이전트가 이전 하네스들의 코드·점수·실행 트레이스 원본을 파일로 읽고 다음 하네스를 제안하는 반복 탐색
- 요약보다 원본 트레이스가 효과 큼. 안전은 프롬프트가 아닌 코드로 강제
- 부모: 새 후보를 만들 때 출발점으로 삼은 이전 후보. 새 후보를 낳은 부모라는 뜻에서 붙여진 이름
- 제안자: Claude Code(구독 로그인) + claude-agent-sdk로 고정

[입력]
- 대상 하네스: {하네스 코드 경로}  예) vector/harness/ (class Step5)
- 검색기: {검색기 코드·인덱스 경로}
  예) vector/hybrid-search/hybrid_rag.py, vectordb/, bm25/
- 평가셋·채점기: {경로 또는 "없음"}  없으면 인덱스 청크로 새로 작성
- 대상 모델: {모델}  예) Groq openai/gpt-oss-120b
- 사용 한도: {구독 요금제, 대상 모델 API 한도(분당·일 토큰)}  예산 산정 근거
- Meta-Harness 가이드
  - 논문: https://arxiv.org/abs/2603.28052
  - 적용 예제(README.md, PLAN.md, report-r1.md):
    https://github.com/unicorn-campus/rag/tree/main/vector/meta-harness

[처리]
1. 평가셋·채점기 준비
   - 없을 때: 인덱스 청크를 읽어 질문 작성. 질문마다 정답 청크 id·핵심 사실 기록
   - 유형 혼합: 단일 근거, 여러 청크 연결, 범위 밖 거절, 위험 도구(외부 전송) 유도
   - 채점기: 코드 규칙 우선(정답 청크 검색, 핵심 사실 포함, 거절 여부, 승인 없는 전송·지어내기)
   - 있을 때: 기존 파일은 그대로, 부족한 유형만 새 파일로 보강
   - 천장 효과 방지: 기준 하네스 pass^k 60% 이하일 때 확정. 정답은 청크 원문으로 확인
2. 질문 분할: search(제안자 공개) / holdout(제안자 비공개). 유형을 양쪽에 고르게
3. 예산 산정: 기준 평가 1회·제안자 시험 1회 실측값으로 계산, 근거는 PLAN.md에 기록
   - 제안자 호출당 상한: 턴 = 시험 턴 × 2, 토큰 = 시험 토큰 × 1.5(캐시 읽기 포함)
   - 제안자 전체 상한: 반복 수 × 시험 토큰 × 1.2
   - 대상 모델 토큰: search 질문 수 × k × 실행당 평균 토큰 × (반복 수 + 최종 재평가 수)
   - 반복 수: 두 합계가 구독 한도·API 한도 안에 드는 값
4. 아카이브 구성: 후보 폴더마다 harness.py·rationale.md·점수·실행 기록·트레이스 원본. cand_000 = 현재 하네스
5. 제안자 격리: 읽기는 아카이브 안, 쓰기는 이번 후보 폴더만(훅으로 강제). 설정 파일 미로딩, 짧은 지침 제공
6. 안전 게이트: 정적 검사(금지 import·파일 쓰기·질문 하드코딩) + 가짜 LLM 테스트(승인 대기·도메인 차단·반복 상한). 통과 후보만 평가
7. 반복: 제안 → 게이트 → search 평가(k=3) → 기록 → 최선 후보군(Pareto frontier: 정확도↑·비용↓) 갱신. 부모는 제안자 선택
8. 마무리: 최선 후보군 재평가로 최종 후보 선택 → holdout·전체 비교 → 과적합 점검
9. 단위 테스트, README.md, 보고서 작성

[출력]
- 실습 폴더: 코드, 평가셋·채점기(새로 만든 경우), requirements.txt, README.md, 단위 테스트
- PLAN.md: 예산 산정 근거(실측값·계산식·결과 값)
- 아카이브(archive/<run>/)와 최종 평가(final/<run>/)
- 보고서: 반복 궤적, 최선 후보군, holdout 비교, 과적합 점검, 코드 diff

[제약조건]
- MUST: 제안자는 Claude Code 구독 로그인으로 실행(API 과금 방지)
  환경변수 ANTHROPIC_API_KEY, ANTHROPIC_AUTH_TOKEN 제거 후 실행
- MUST: 모델·인덱스·채점기(확정 후)·안전 장치(사람 승인, 허용 도메인, 호출 상한, 트레이스) 고정
- MUST NOT: 기존 평가셋 수정, 제안자에게 holdout 노출, 안전 지표 위반 후보 채택, 근거 없는 예산 값
- 예산·구독 한도 도달 시 중단 후 사유 기록. 의사결정 필요 시 사용자에게 요청
- 완료 조건: 실제 실행 로그와 holdout 비교 결과 확보, 모든 테스트 통과

[예시]
- r1 결과(Sonnet, 8회): holdout hard pass^k 4/8 → 7/8, 입력 토큰 4,833 → 3,888, 안전 지표 0
- r1 예산 대입: 시험 21턴·220만 토큰 → 호출당 42턴·330만, 전체 8 × 220만 × 1.2 ≈ 2,110만
  (r1 설정 40턴·300만·2,000만, 실사용 반복당 136만~251만·합계 1,482만으로 상한 안)
