# 범위 판별 실험(scope filter)

스키마 채우기 시험에서 지어냄 비율이 기준(0.1 이하)에 닿지 못한 원인이 스키마가 아니라 추출 단위와 범위에 있는지 확인하는 별도 실험. 원래 프로그램(`graphrag/schema/`, `graphrag/index/`)은 고치지 않고, 함수와 입력 파일(`fill-test-expected.json`, `work/round-5.json`, `work/schema-draft-r2.confirmed.json`, `competency-questions.md`)을 읽기만 함. 출력은 이 폴더에만 씀.

## 1. 용어

- 지어냄 비율(hallucination rate): 뽑힌 항목 중 사람이 확정한 기대 결과에 없는 항목의 비율. 기준 0.1 이하
- 재현율(recall): 기대 항목 중 뽑힌 항목의 비율. 기준 0.8 이상
- 범위 판별(scope filter): 역량질문(그래프가 답해야 하는 질문)과 관련된 조문에서 나온 항목만 남기는 일. 조문 번호 규칙이라 LLM을 부르지 않음
- 조 단위(article unit): 청크 본문을 `제N조(…)` 머리로 나눈 조문 하나

## 2. 실험 구성

| 실험 | 파일 | 추출 | 범위 판별 |
|---|---|---|---|
| 1. 조 단위 | `article_test.py` → `article-test-report.md` | 조문을 하나씩 떼어 따로 추출(3회) | 범위 밖 조문의 결과를 버림 |
| 2. 청크 문맥 | `context_scope_test.py` → `context-scope-report.md` | 청크 전체로 추출(문맥 유지). 5회차 저장 결과 3회 + 새로 3회 | 노드 이름이 범위 안 조문에서 나왔는지 규칙으로 판별해 남김 |

- 범위 D: 역량질문 표의 '답이 있는 대표 조문'(제29·32·59·88·96·126·128·132조의17·225조)
- 범위 D+: D + 제33조(특허를 받을 수 있는 자, HOLDS 관계) + 제132조의16(특허심판원, CQ04 처리 기관)
- 스키마·추출 프롬프트·채점은 채우기 시험 5회차와 같음(최종 스키마, 라이브러리 기본 프롬프트, 3회 반복 평균)

## 3. 결과

| 방식 | 재현율 | 지어냄 비율 | 역량질문 |
|---|---|---|---|
| 기준: 청크 단위(5회차 재채점) | 0.873 | 0.274 | 8/9 |
| 실험 1-A 조 단위만 | 0.710 | 0.402 | 9/9 |
| 실험 1-B 조 단위 + 범위 D | 0.635 | **0.086** | 7/9 |
| 실험 1-C 청크 단위 + 범위 밖 청크만 제외 | 0.873 | 0.217 | 8/9 |
| **실험 2 청크 문맥 + 범위 D+(통째 일치), 5회차 결과** | **0.786** | **0.132** | **8/9** |
| 실험 2 청크 문맥 + 범위 D+(통째 일치), 새 실행 | 0.726 | 0.137 | 8/9 |
| 실험 2 청크 문맥 + 범위 D+(단어 귀속), 5회차 결과 | 0.631 | 0.102 | 4/9 |
| 참고: 새 실행 기준(거르지 않음) | 0.782 | 0.402 | 9/9 |

## 4. 해석

- 지어냄을 줄이는 것은 범위 판별임. 범위 밖 조문(전자문서 제28조의3·4, 존속기간 연장 제89조, 송달 제218 ~ 222조, 소송기록 제224조의5)에서 나오던 지어냄이 빠짐
- 조문을 따로 떼어 추출하는 방식(실험 1)은 쓰지 않는 것이 나음
  - 조 단위로 나누기만 하면 지어냄이 오히려 늘어남(0.402). 범위 밖 조문만 따로 주면 LLM이 그 조문에서도 절차·기관을 뽑음
  - 짧은 조문 하나만 주면 LLM이 빈 결과를 돌려줌(제88조 3회 모두 `{"nodes": [], "relationships": []}`, CQ06 실패)
  - 조문을 넘나드는 관계를 잃음(제132조의16 특허심판원 ↔ 제132조의17 심판, CQ04 실패)
- 청크 문맥으로 추출하고 범위로 거르는 방식(실험 2, D+, 통째 일치)이 가장 균형이 좋음
  - 지어냄 비율이 절반 이하로 내려감(5회차 0.274 → 0.132, 새 실행 0.402 → 0.137). 실행마다 크게 흔들리던 지어냄(0.274와 0.402)이 0.13 근처로 고르게 됨
  - 대신 재현율이 0.06 ~ 0.09 내려감(0.786, 0.726). 이름 규칙상 괄호 속 부연을 빼고 이름을 만들어 본문에 글자 그대로 없는 항목(예: '침해행위를 조성한 물건의 폐기', '연구 또는 시험을 하기 위한 특허발명의 실시')이 같이 지워짐
  - 역량질문은 8/9로 기준과 같음(CQ04는 여전히 불안정)
- 단어 귀속 규칙은 실패. '특허', '특허권', '전용실시권자'처럼 짧은 이름이 범위 밖 조문으로 귀속되어 맞는 항목까지 지워짐(역량질문 4/9). 시험 자료에 맞춰 규칙을 더 고치면 과적합 위험이 있어 더 손보지 않음
- 기준을 모두 넘은 방식은 없음(재현율 0.8 이상, 지어냄 0.1 이하, 역량질문 9/9 동시 충족 없음)
- 실행 변동: 같은 설정의 기준도 5회차와 새 실행 사이에 지어냄 0.274와 0.402로 크게 다름. 3회 평균도 실행 묶음에 따라 흔들리므로 0.01 ~ 0.02 차이는 의미 있게 보지 않음

## 5. 다음 후보

- 출처 판별을 이름이 아니라 추출 단계에서 받기: 추출 프롬프트에 "각 노드에 근거 조문 번호를 붙임"을 넣어 조문 번호로 거름(추출 프롬프트를 바꾸므로 원래 시험과 조건이 달라짐)
- 통째 일치에서 괄호 속 부연을 지운 조문 본문으로도 비교해, 이름 규칙 때문에 지워지는 항목을 살림
- 범위 목록을 역량질문 대표 조문에서 정하는 대신, 스키마 패턴별로 필요한 조문(제33조 HOLDS, 제132조의16 처리 기관 등)을 사람이 확정

## 6. 실행 방법

저장소 루트(`rag/`)에서 실행함. 패키지는 `graphrag/schema/requirements.txt`와 같음.

```bash
python graphrag/experiments/scope_filter/article_test.py --repeat 3
```

```bash
python graphrag/experiments/scope_filter/context_scope_test.py --repeat 3
```

- `--rescore`: LLM 호출 없이 `results/`의 저장 결과로 다시 채점
- 원자료: `results/article-test.json`(실험 1 조문별 추출 결과), `results/context-scope.json`(실험 2 새 실행 추출 결과)
- chromadb로 `vectordb/`를 읽기만 해도 파일이 갱신되어 git 변경으로 잡힘. 커밋하지 말고 `git restore vectordb/`로 되돌림
