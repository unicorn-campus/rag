# Meta-Harness로 하네스 발전시키기: 수행 계획서

작성 2026-11-08 · 출발점 `vector/harness` 5단계 하네스(프롬프트 v3) · 상태: **승인됨(2026-11-08)** · 제안자는 claude.ai 팀 구독으로 실행

## 1. 목적

교재 63p의 **Meta-Harness**(arXiv 2603.28052)로 **현재 하네스를 한 단계 더 발전**시킵니다.
고장 난 곳을 고치는 개선 루프가 아니라, 현재 하네스가 아직 못 하는 일을 하게 만드는 것이 목표입니다. 여러 조문을 엮는 답, 예외 조문까지 챙기는 답, 같은 품질을 더 적은 토큰·시간으로 내는 것이 그런 일입니다.

방법은 논문과 같습니다. 코딩 에이전트가 이전 하네스들의 **코드·점수·실행 트레이스**를 파일로 직접 읽고 **새 하네스 코드**를 제안합니다. 이 과정을 반복해 현재 하네스보다 나은 하네스를 찾습니다.

**성공 기준:** 제안자가 보지 않은 질문(holdout)에서, 안전 지표를 지키면서 아래 셋 중 하나 이상이 기준(현재 v3)보다 편차를 넘어 좋아지면 성공입니다.
1. 어려운 질문의 pass^k가 오름
2. 기존 질문에서 점수를 유지하면서 토큰 또는 시간이 줄어듦
3. 둘 다

## 2. 왜 평가 질문을 더 어렵게 해야 하나 (천장 효과)

현재 하네스는 기존 20문항에서 이미 pass@k 20/20, pass^k 18/20입니다. 이 질문만으로는 더 나아져도 점수에 거의 드러나지 않습니다.
그래서 **어려운 질문 20개(hard set)**를 새로 만들어, 발전할 여지가 보이는 곳에서 잽니다.

| 유형 | 예시(안) | 현재 하네스가 약한 이유 |
|---|---|---|
| 여러 조문 엮기 | 거절결정 불복: 누가, 언제까지, 어디에 | 검색 1~3번으로 근거가 흩어짐 |
| 원칙과 예외 | 공지된 발명도 특허를 받는 경우(제29조 + 제30조) | Q2처럼 예외 조문을 못 찾음 |
| 기한·숫자 | 연장등록출원 기한, 존속기간 연장 상한 | 숫자를 원문 그대로 확인해야 함 |
| 절차 연결 | 출원 → 심사청구 → 거절이유통지 → 보정 순서 | 단계마다 다른 조문 |
| 틀린 전제 | "특허권은 출원일부터 10년이죠?" | 전제를 바로잡아야 함 |
| 비교 | 전용실시권과 통상실시권의 차이 | 두 조문을 나란히 비교 |

각 질문은 원문 청크에서 정답 조문과 핵심 사실(기한·숫자·주체)을 확인하고, 코드로 채점합니다(필요 조문 모두 언급 + 핵심 사실 포함 + 근거 일치). 기준 하네스로 먼저 재서 **pass^k가 60% 이하**로 나와야 hard set으로 확정합니다. 너무 쉬우면 질문을 교체합니다.

## 3. 논문에서 가져올 핵심 (교재 63p + 논문 본문 확인)

| 항목 | 논문 | 이 실습 |
|---|---|---|
| 제안자 | Claude Code(Opus 4.6) + 짧은 지침(skill) | Claude Code를 `claude-agent-sdk`로 헤드리스 실행 + `skill/PROPOSER.md` |
| 기록 | 후보마다 소스·점수·트레이스를 폴더로 | 후보 폴더에 `harness.py`·`scores.json`·`runs.jsonl`·`traces/*.jsonl` |
| 진단 | grep·cat으로 필요한 파일만 읽음(반복당 약 82개 파일) | 읽기 도구 Read·Grep·Glob만 허용 |
| 제안 | 일부 수정 또는 **전면 재작성** | 문구 수정보다 **새 구조·새 장치** 제안을 권장 |
| 선택 | 부모 선택 규칙 없음. 정확도·비용 Pareto 전선 유지 | 정확도(hard pass^k)·비용(입력 토큰) Pareto 전선 |
| 과적합 방지 | 제안자는 test 결과를 보지 않음 | 기존·hard 모두 search / holdout으로 나누고 holdout은 아카이브에 넣지 않음 |
| 교훈 | 요약보다 **원본 트레이스**가 효과 큼(Table 3: 중앙값 34.9 → 50.0) | 요약 대신 실행 기록 원본을 그대로 둠 |
| 비용 | 반복당 약 1,000만 토큰 | 반복 수·제안자 비용 상한을 코드로 둠(7장) |

## 4. 탐색 범위: 무엇을 새로 만들 수 있고, 무엇은 고정하나

| 구분 | 내용 |
|---|---|
| **새로 만들 수 있음** | 시스템 프롬프트·도구 설명, **새 읽기 전용 도구**(예: 조문 번호로 원문 바로 찾기, 앞뒤 청크 펼치기), **검색 전략**(질문 분해, 여러 검색어, 원칙 조문 뒤 예외 조문 검색), **계획 단계**(하위 질문 목록 → 하나씩 확인), 근거 대조 강화(핵심 숫자·기한이 원문에 있는지), 컨텍스트 정리(지난 검색 결과 줄이기), 상한·예산 값 조정, 재생성·부분 결과 전략 |
| **고정(안전)** | 모델 Groq `gpt-oss-120b`, 인덱스 데이터(`vectordb/`, `bm25/`, 쓰기 금지), 채점기, 평가 질문, **외부 전송 사람 승인(HITL)**, 메일 허용 도메인, 반복·예산 상한의 **존재**(값은 조정 가능), 트레이스 기록 |

- 후보는 `class Candidate(Step5)` 형태의 파일 하나(`harness.py`)로 만듭니다.
- 메서드를 바꾸는 것은 물론, 새 도구·새 미들웨어·새 처리 단계를 더해도 됩니다.
- 새 도구는 기존 인덱스를 **읽기만** 해야 합니다.

## 5. 폴더 구성 (`vector/meta-harness/`)

```
PLAN.md                 이 계획서
README.md               실행법·결과(완료 후)
hard_questions.py       어려운 질문 20개 + 채점기(조문·핵심 사실·근거). 새 파일
splits.py               기존 20·hard 20을 각각 search 12 / holdout 8로 분할(기존 질문은 import만)
meta_loop.py            바깥 루프: 제안 → 안전 게이트 → 평가 → 기록 → 전선 갱신
proposer.py             Claude Code 호출(claude-agent-sdk), 도구·쓰기 경로 제한, 비용 기록
evaluator.py            후보 import → search/holdout 평가(기존 채점기 + hard 채점기)
safety_gate.py          정적 검사 + 안전 테스트(가짜 LLM)
skill/PROPOSER.md       제안자 지침(목표, 읽을 곳, 쓸 곳, 고정 항목, 금지 사항)
archive/<run_id>/
  cand_000/             기준 = 현재 Step5(v3)
    harness.py  scores.json  runs.jsonl  traces/*.jsonl
  cand_001/ ...         harness.py + rationale.md(가설, 바꾼 구조, 노리는 지표)
  frontier.json         Pareto 전선
  history.jsonl         반복별 점수·비용·게이트 결과
report.md               궤적, 전선, 최종 후보의 새 구조와 기준 대비 diff, holdout 결과, 비용
test_meta.py            단위 테스트(가짜 제안자·가짜 LLM)
```

## 6. 반복 1회의 흐름

1. **제안** — Claude Code를 `archive/<run_id>/`에서 실행합니다.
   - 도구는 Read·Grep·Glob만 쓰고, Write는 `cand_<i>/` 안에서만 허용합니다(`can_use_tool` 훅으로 코드가 강제).
   - 사용자 설정·프로젝트 CLAUDE.md는 읽지 않게 격리합니다(`setting_sources=[]`).
   - 지침의 목표는 "현재 하네스가 못 하는 일을 하게 만들라"입니다. 트레이스에서 약점(검색이 부족한 질문 유형, 토큰이 많이 드는 단계)을 찾고, 그것을 해결할 **가설과 새 구조**를 `rationale.md`에 먼저 쓴 뒤 `harness.py`를 쓰게 합니다.
2. **안전 게이트(코드)** — 통과해야 평가합니다.
   - 정적 검사: import 가능, `Step5` 상속, HITL 미들웨어·허용 도메인·상한 미들웨어 존재, 금지 패턴(인덱스 쓰기, 채점기·평가 파일 접근, `subprocess`, 네트워크, 파일 쓰기, 평가 질문 문자열 하드코딩) 없음
   - 안전 테스트(가짜 LLM): 승인 전 전송 0건, 허용 밖 도메인 차단, 반복 상한 작동
3. **평가** — search 세트(기존 12 + hard 12) × 3회 = 72회입니다.
   - 잴 지표: 정확도(hard pass^k가 핵심, 기존 pass^k), 비용(입력 토큰), 시간, 실패 유형
   - 실행 기록과 트레이스 원본을 후보 폴더에 남깁니다.
   - 안전 지표(승인 없는 전송, 범위 밖 지어내기)가 0이 아니거나, 기존 search pass^k가 기준보다 편차 이상 떨어지면 탈락입니다.
4. **기록·선택** — `history.jsonl`에 남기고 Pareto 전선(hard pass^k ↑, 입력 토큰 ↓)을 갱신합니다. 다음 부모는 지정하지 않고 제안자가 아카이브를 보고 고릅니다(논문 방식).

## 7. 예산 (메타 루프에도 하네스를 둠, 구독 기준)

제안자는 로컬 Claude Code의 **claude.ai 팀 구독 로그인**으로 실행합니다(`claude auth status`: authMethod `claude.ai`, subscriptionType `team`). 그래서 예산은 금액이 아니라 **사용량(턴·토큰)**으로 잡습니다. Claude Code가 보여 주는 `total_cost_usd`는 API 요금 환산 추정치이므로 참고용으로만 기록합니다.

| 항목 | 기본값 | 근거 |
|---|---|---|
| 반복 수 | 8회(반복당 후보 1개) | 논문 TerminalBench-2 10회. 사용량을 고려해 줄임 |
| 제안자 1회 | 최대 40턴, 입력+출력 토큰 상한 300만(캐시 읽기 포함) | 논문 반복당 약 1,000만 토큰의 1/3 수준 |
| 제안자 전체 | 토큰 상한 2,000만 | 넘으면 루프 중단, 부분 결과와 사유 기록 |
| 구독 사용 한도 | 한도 도달 오류가 나면 그 반복을 멈추고 기록 | 다음 실행에서 `--resume`으로 이어 감 |
| API 과금 방지 | 제안자를 띄울 때 `ANTHROPIC_API_KEY`·`ANTHROPIC_AUTH_TOKEN` 환경 변수를 지움 | 구독 대신 API로 과금되는 일을 막음 |
| 평가 | 후보당 72회(Groq), 최종 holdout 16문항×3회 + 전체 40문항×3회 | k=3 유지 |
| 시간 | 반복당 20분 | 넘는 단계는 건너뛰고 기록 |

제안자 모델은 **Sonnet으로 1회 시험 반복을 한 뒤 결정**합니다. Opus는 구독 사용 한도를 훨씬 빨리 씁니다. 시험 반복에서 Sonnet이 아카이브를 읽고 동작하는 후보를 만들면 Sonnet으로 계속 진행하고, 그 판단 근거를 보고서에 남깁니다.

## 8. 과적합 방지와 평가 설계

- **분할(유형별로 나눔):**
  - 기존 20: search 12(Q1·Q3·Q5·Q6·Q8·Q10·Q12·Q13·Q15·Q17·Q18·Q20) / holdout 8(Q2·Q4·Q7·Q9·Q11·Q14·Q16·Q19)
  - hard 20: 유형(2장 표)별로 고르게 search 12 / holdout 8
- 제안자에게는 search 결과와 트레이스만 보입니다. holdout 질문과 결과는 아카이브 밖에 둡니다.
- **편차 대비:** 질문 12개 × 3회는 질문 1개가 8.3%p라 운이 크게 섞입니다. 전선에 오른 후보는 search를 한 번 더 돌려 평균으로 판단합니다.
- **최종 비교:** 기준(cand_000 = 현재 v3) 대 최종 후보를 holdout(16문항)과 전체(40문항)에서 비교합니다. 비교 지표는 hard pass^k, 기존 pass^k, 토큰, 시간입니다. 나아지지 않으면 그대로 보고합니다.

| 단계 | 할 일 | 완료 기준(증거) |
|---|---|---|

| P1 | 분할, 기준 후보 아카이브(cand_000 평가) | search 점수·트레이스 파일 생성 |

| P3 | 제안자 연결, 1회 시험 반복 | 제안자가 아카이브를 읽고 cand_001을 써서 평가까지 끝남, 비용 기록 |

| P6(선택) | 교재 장표 | 63p 뒤에 실습 결과 1장 |
