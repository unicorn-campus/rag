# cand_006 rationale

## 부모
cand_005 (base 10/12, hard 8/12, hard 통과율 0.75, 입력 4652). 가장 균형이 좋고 prefetch + 조문 라벨 구조가 안정적이다. 남은 hard 실패는 모두 "검색은 됐지만 후속 단계 조문이 없다"는 유형이다.

## 진단 (근거: cand_005 runs-search.jsonl, scores-search.json)
- H1 0/3 (missing_fact 3회): retrieved=[153,116,118,132,...]에 제186조(심결 취소소송 제기기간·법원) 청크가 없다. 답은 제189조·제132조의17만 인용하고 "심결 후 소 제기 기간·법원"은 환각이나 누락(한 번은 제190조제2항 30일로 잘못 인용, 한 번은 제163조 일사부재리로 빗나감). EXPANSIONS의 "심결 취소소송 법원 제기" 검색은 제189조까지만 끌어온다. 검색어로는 절차 다음 단계 조문이 안 잡힌다.
- H13 1/3 (missing_fact 2회): 청크 33(제47조)는 3번 모두 검색됐는데, 답이 제47조제1항의 모든 시기(특허결정 등본 송달 전, 의견서 제출기간, 재심사 청구 시)를 빠뜨리거나 일부만 쓴다. 통과한 실행은 항·호를 길게 열거한 것 하나다. 즉 시기·범위처럼 열거형 질문에서 호 누락이 원인이다.
- H2 0/3, H18 2/3도 같은 패턴(핵심 사실 일부 누락)이다. 원문은 있으나 답이 한 항만 쓴다.
- 반면 H4·H8·H9·H14는 cand_005에서 3/3으로 복원됐고 안전 지표는 0이다. 유지해야 한다.

## 가설
1. 법률 용어 → "함께 봐야 하는 조문 번호" 연결표(도메인 지식, 질문 문장 아님)를 코드에 두고, 질문에 용어가 있으면 그 조문 청크를 번호로 직접 찾아 prefetch에 넣는다(읽기 전용, record 처리). 심결→제186조, 거절결정 불복→제132조의17, 보정→제47조, 재심사→제67조의2, 정정→제136조, 존속기간 연장→제89·90조, 무효심판→제133조, 통상실시권 허락→제102조 등. 검색 의존을 끊어 H1류의 "다음 단계 조문 누락"을 막는다.
2. 지시문에 "조문이 항·호로 나뉘어 시기·요건·사유를 묻는 질문은 원문의 모든 호를 빠짐없이 열거하고, 소·심판은 제기 기간과 관할 기관(법원 명칭)을 반드시 쓴다"를 추가해 H13의 호 누락을 줄인다.
3. 링크 청크는 라벨(포함 조문)이 붙어 있어 조문 번호 인용이 유지된다.

## 바꾼 구조
- cand_005 코드 복사 후: (a) `ARTICLE_LINKS` 표와 `find_article_chunks()` 추가(조문 머리 `제N조(` 패턴으로 청크 찾기, 이어지는 청크 1개 포함), (b) `prefetch_ids`에서 링크 청크를 검색 결과 앞쪽에 합치되 상한을 10으로 늘림, (c) prefetch 조건에 링크 용어 일치 포함, (d) PREFETCH_NOTE에 열거·기간·관할 규칙 추가.
- 시스템 프롬프트·도구·send_email·승인·상한·finish·트레이스는 Step5 그대로. 메일 요청은 prefetch 제외.

## 노리는 지표
- hard pass^k: H1 0→2~3, H13 1→3 (목표 hard 9~10/12). H4·H8·H9·H14 유지.
- base pass^k 10/12 유지, 입력 토큰 +300 내외(~5.0k).
- unapproved_send, hallucination 0.

## 예상 위험
- 링크 청크가 잡음이 되어 ungrounded 증가 → 용어당 조문 1~2개, 총 청크 상한 10, 청크 글자 상한 1600 유지.
- 열거 지시로 답이 길어져 6문장 초과 → "6문장 이내, 호 열거는 한 문장에 묶어" 문구로 완화.
- 용어가 넓게 일치(예: "보정"이 다른 질문에 등장)하면 입력 토큰 증가. 질문당 링크 조문은 최대 3개로 제한.
