# cand_003 rationale

## 부모
cand_000(hard pass^k 8/12, 토큰 4478)을 기반으로, cand_002에서 효과가 확인된 `find_article`만 가져옴.
cand_001(다중 검색어)·cand_002(이어지는 청크 자동 첨부, 토큰 8074)는 입력 토큰만 늘고 hard가 오히려 떨어져 구조 전체는 버림.

## 진단 (근거: cand_000/002 scores-search.json, cand_002 runs-search.jsonl)
- cand_002 hard by_q: H1 0→2/3(find_article로 심결 불복 조문 도달), H13 0/3, H4 0/3, H2 2→0, H14 3→2, H5 3→2. 평균 입력 토큰 hard 10227.
- H13 실행 기록: retrieved=[33,29,34,38]인데 답은 C033만 인용, 실패 유형 missing_fact. **청크는 검색됐지만 모델이 첫 청크만 읽고 쓴다.** 즉 문제는 검색이 아니라 "답 작성 시 검색된 자료를 다 훑지 않음"이다.
- 모델은 첫 검색에서 멈추고(모델 호출 약 2.2회) 선택형 도구는 거의 안 쓴다. 프롬프트 지시로는 행동이 안 바뀐다 → 코드가 강제하는 단계가 필요.
- cand_002의 자동 이어붙이기는 모든 질문에 청크를 더해 토큰을 두 배로 늘렸고(2순위 지표 악화), 관련 없는 청크가 섞여 H2·H5 회귀 가능성.

## 가설
1. **검토 단계(review pass)**: 답이 나온 뒤 코드가 한 번 더 LLM을 불러, 질문의 요소(주체·기한·숫자·원칙/예외·다음 단계·틀린 전제)를 열거하고 **이미 검색된 모든 청크**와 초안을 대조해 빠진 사실을 보강한 답을 JSON으로 받는다. 새 검색이 아니라 이미 가진 자료의 재독이라 missing_fact/wrong_answer에 직접 작용한다.
2. 검토는 복합 질문으로 보이는 경우(코드 휴리스틱)에만 돌려 base 질문의 토큰을 지킨다. 청크는 최대 6개, 각 1400자로 자른다.
3. 검토 결과는 기존 근거 대조(check_grounding)를 다시 통과해야 채택, 실패·파싱 오류면 초안 유지(안전). 검토는 새 조문을 지어내지 못하게 "자료에 없는 것은 쓰지 않음" 규칙.
4. `find_article`(조문 번호로 원문 청크 찾기)과 짧은 절차 지도 힌트로 H1·H4류 후속 단계 조문 접근 유지. 검색 결과 자동 첨부는 하지 않음.

## 바꾼 구조
- `tools()`: contract_tools() 그대로 + 읽기 전용 `find_article`(찾은 청크를 tracker().retrieved에 기록).
- `system_prompt()`: 부모 + 짧은 복합 질문 규칙·절차 지도.
- `finish()`: super().finish(검증·차단 포함) 뒤에 `review_pass`. 차단된 답·거절·부분 결과는 건드리지 않음.
- send_email, HITL, 상한, 트레이스는 상속 그대로.

## 노리는 지표
- hard pass^k: H13(보정 범위·시기 항 누락), H1/H4(절차 연결 사실 누락), H2·H14 회복.
- 입력 토큰: 복합 질문에만 약 +3~4k, 기존 질문은 대부분 +0. 기준 4478보다 늘지만 cand_002(8074)보다 작게.
- unapproved_send, hallucination 0 유지.

## 예상 위험
- 검토 호출이 초안의 맞는 부분을 깎거나 근거 없는 조문을 넣을 수 있음 → 근거 대조 재통과 필수, 실패 시 초안 유지.
- 휴리스틱이 단순 질문까지 잡으면 토큰 증가.
- 검토 LLM이 JSON을 못 내면(Groq) 초안 유지라 개선 없음(손해도 없음).
