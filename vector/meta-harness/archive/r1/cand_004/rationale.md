# cand_004 rationale

## 부모
cand_000 (hard 8/12, 입력 토큰 4478). 시스템 프롬프트·도구·finish는 그대로 두고, 질문이 들어오는 입구(`invoke`)에만 코드 단계를 더한다.
cand_001(다중 검색어 도구)·cand_002(청크 자동 이어붙이기)·cand_003(답 뒤 LLM 검토)은 모두 hard가 cand_000 이하라 구조를 버린다.

## 진단 (근거: 네 후보의 scores-search.json by_q, cand_000/cand_003 runs-search.jsonl)
- cand_000 hard 0/3: H1(거절결정 불복 심판 + 심결 불복), H4(심판 말고 재심사 + 기한), H13(보정 시기·범위). H1·H4는 `missed_evidence`: 모델이 **첫 검색 한 번**(retrieved=[132,148,116,118] 또는 [59])에서 멈추고, 질문의 두 번째 절(심결 불복, 비교 대상인 심판)에 해당하는 조문 청크를 한 번도 검색하지 않았다.
- cand_003은 find_article·검토로 H1 2/3, H4 2/3, H13 1/3을 얻었으나 H20 3→0, H2 2→0, H18 3→1로 **더 많이 잃었다**.
  - H20(전용실시권/통상실시권) 실행 기록: 검색을 `"전용실시권"` 하나만 해서 retrieved=[84,85,88,87]에 통상실시권 조문(C086)이 없음 → 모델이 검색어를 질문의 절 하나로만 만드는 변동이 원인. cand_000에서는 3/3이었으니 **모델 검색어 선택의 운**이 점수를 가른다.
  - H2(민사·형사 조치) 실행 기록: retrieved=[107,103,102,189,187,188]에 금지청구 조문(C100)이 없고, 검토 단계가 답을 다시 써 제126조를 더 놓침(모델 호출 4회, 입력 11575).
- 결론: 병목은 답 작성이 아니라 **검색어의 질문 요소 커버리지**이고, 모델에게 "여러 번 검색하라"고 시키거나(프롬프트·도구) 뒤에서 고치는(검토) 방식은 불안정하다. 검색 커버리지는 모델 판단이 아니라 코드가 보장해야 한다.

## 가설
질문을 코드가 규칙으로 절 단위(물음표·쉼표·"와/과"·"및"·"말고"·연결어미)로 쪼개 각 절을 하이브리드 검색기에 보내고, 결과를 라운드로빈으로 합쳐(최대 7청크) **모델이 첫 호출을 하기 전에** 자료로 준다.
- 복합 질문의 각 요소(심결 불복, 비교 대상 심판, 통상실시권, 형사 조항 등)가 최소 한 번은 검색되므로 `missed_evidence`가 줄고, 모델은 이미 넓은 자료를 보고 쓰므로 `missing_fact`도 줄 것이다.
- 자료가 충분하면 모델이 추가 검색 없이 답해(모델 호출 감소) 입력 토큰 증가를 상쇄한다. 부족하면 기존 도구로 더 검색한다.
- LLM을 더 부르지 않는다(분해는 정규식). 새 환각 경로·검토 회귀가 없다.

## 바꾼 구조
- `invoke`만 덮어씀: 복합 질문(절 2개 이상, 메일 요청 아님)이면 `prefetch()`로 `common.record_search`를 절마다 호출(질문 전체 상위 2 + 절별 상위 2, 최대 4절, 7청크, 청크당 1600자)하고, 결과를 `<doc id="C073">` 형식으로 사용자 메시지에 덧붙여 에이전트를 실행. 승인 이어 하기 루프(Step4)는 그대로 복사해 send_email 승인 흐름 유지.
- `tracker().retrieved`에 사전 검색 청크가 기록되어 근거 대조·채점이 인정. 이벤트 `prefetch`로 쪼갠 절과 청크를 남김.
- 시스템 프롬프트·도구(send_email 포함)·미들웨어·상한·finish·트레이스는 상속 그대로. 단순 질문(Q 대부분)은 경로가 같아 토큰·점수 변화 없음.

## 노리는 지표

## 예상 위험
- 규칙 분해가 어색한 절을 만들어 잡음 청크가 섞일 수 있음 → 청크 7개 상한과 절당 2개로 억제, 근거 대조가 잘못된 인용을 막음.
- 모델이 사전 자료만 믿고 부족한 요소를 추가 검색하지 않을 수 있음 → 메시지에 "빠진 요소는 그 요소만 검색" 지시.
- H13처럼 한 조문 안 항·호 사실 누락은 이 장치로 직접 해결되지 않을 수 있음.
