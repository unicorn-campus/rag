# cand_002 rationale

## 부모
cand_000 (hard pass^k 8/12, 입력 토큰 4478). cand_001(다중 검색어 + 선택형 이웃 도구)은 hard 5/12, 토큰 5965로 부모보다 나빠서 버림.

## 진단 (근거: cand_000/cand_001 runs-search.jsonl)
- hard 상시 실패: H1(0/3), H4(0/3), H13(0/3), H2(cand_001에서 0/3). 실패 유형은 missed_evidence, missing_fact, wrong_answer.
- H1(거절결정 불복: 심판 → 심결 불복) cand_000은 검색 1번(retrieved=[132,148,116,118])만 하고 심결 뒤 단계를 **재심(제180조)** 으로 잘못 답함. 심결 불복 소송 조문 청크는 한 번도 검색되지 않음.
  cand_001은 검색어 3개를 던졌지만("심결 불복", "심판결과 불복") 그래도 해당 청크가 안 올라왔고, 한 번은 검색하지 않은 C180을 인용해 근거 대조에서 차단(verify_failed). → **BM25/벡터 검색어로는 못 찾는 조문이 있음. 조문 번호로 직접 찾는 길이 필요.**
- H13(거절이유통지 후 보정 시기·범위) 3회 모두 [33,29,34,38] 중 C033(, 가끔 C034)만 인용, `missing_fact`. 한 조문이 여러 청크로 쪼개져 있어 항·호의 뒷부분이 답에서 빠짐 → **조문 이어지는 청크를 자동으로 붙여야 함.** cand_001의 read_nearby_chunks는 선택 도구라 모델이 한 번도 안 불러서 효과 0.
- 공통: 모델은 첫 검색에서 멈춤(평균 모델 호출 2.2). 선택형 새 도구는 안 쓴다 → **코드가 강제로 하는 장치**(검색 결과에 이어지는 청크 자동 첨부)와 **프롬프트의 절차 지도**(어느 조문을 이어서 봐야 하는지)로 바꿈.

## 가설
1. 검색 도구가 상위 청크의 "다음 청크가 같은 조문의 계속이면" 자동으로 붙여 주면(최대 2개) 항·호 누락(missing_fact)이 줄어든다. 모델 행동에 의존하지 않는다.
2. `find_article(조문번호)` 도구(조문 제목 `제N조(` 로 청크를 찾음)와, 시스템 프롬프트의 짧은 "절차 지도"(거절결정→재심사/심판→심결 소송 같은 연결, 조문 번호는 검증 전 힌트)를 주면, 검색어로 안 잡히는 후속 단계 조문을 찾는다. 찾은 청크는 `tracker().retrieved`에 기록해 근거 대조가 인정한다.
3. 프롬프트에 "하위 질문마다 근거 점검" 체크리스트를 짧게 넣어 원칙·예외·기한·다음 단계 누락을 막는다. 5문장 제한은 복합 질문에 한해 7문장으로 완화.

## 바꾼 구조
- `search_patent_law`: 입력·검색은 그대로(검색어 1개), 결과에 이어지는 청크 자동 첨부(상위 2개 청크에 대해 각 1개, 총 2개 상한).
- 새 `find_article(article)`: "제186조", "186", "제132조의17" 모두 허용. 조문 제목 청크 최대 2개 + 그 이어지는 청크 1개(상한 3). 없으면 고치는 법을 담은 오류.
- `system_prompt`: 부모 프롬프트 + [복합 질문 규칙] + [절차 지도(힌트)]. 힌트 조문은 반드시 find_article/검색 원문으로 확인한 뒤에만 인용하게 함.
- send_email, HITL 승인, 호출 상한, 트레이스, 3단계 근거 대조는 상속 그대로.

## 노리는 지표
- hard pass^k 상승: H1(심결 불복 소송 조문), H13(제47조 뒷부분 항), H4/H2(후속 조문). 검색 호출 수는 늘리지 않고 모델 호출은 3 정도로 예상.
- base 점수 유지. 입력 토큰은 이어지는 청크 때문에 약간 늘 수 있어 첨부는 2개로 제한.
- unapproved_send, hallucination 0 유지.

## 예상 위험
- 청크 첫머리 형식을 정확히 몰라 "이어지는 청크" 판정이 느슨하면 불필요한 청크가 붙어 토큰 증가(상한 2개로 제한).
- 모델이 절차 지도 힌트를 원문 확인 없이 인용하면 ungrounded → 근거 대조가 차단(안전하지만 점수 손실). 프롬프트에 확인 규칙 명시.
- find_article을 안 쓰면 H1 개선 없음(프롬프트에서 후속 단계 질문이면 호출하도록 유도).
