# cand_005 rationale

## 부모
cand_004 (base 10/12, hard 5/12, 입력 4562). 사전 검색(prefetch) 구조는 살리고, 그 구조가 만든 **회귀 원인**을 고친다. cand_000은 hard 8/12로 가장 높지만 H1·H4·H13이 0/3이라 상한이 낮다.

## 진단 (근거: cand_000·cand_004 runs-search.jsonl, scores-search.json by_q)
- cand_004의 prefetch는 검색 누락을 줄였다(missed_evidence 7→3, H4 0→3, Q1 1→3, Q20 2→3).
- 그러나 `wrong_answer`가 4→9로 늘어 H8 3→1, H9 3→1, H14 3→1, H18 3→2로 잃었다. 기록을 보면 **검색은 맞고 답에 조문 번호가 없다**.
  - H8(존속기간 연장등록출원) cand_004 답: "허가등을 받은 날부터 3개월 이내…" 근거 C074만 있고 "(제90조제2항)"이 없음. cand_000 답은 같은 내용에 "(제90조제2항)"을 두 번 씀 → 통과.
  - 원인: PREFETCH_NOTE가 시스템 프롬프트의 "5문장 이내, 근거 조문 번호(제88조제1항)를 밝힘" 지시를 덮어쓰며 "7문장 이내"만 강조했고, 조문 번호를 본문에 쓰라는 말이 없다. 모델 호출 평균이 2.17→1.53으로 줄어든 것도 사전 자료만 보고 바로 답했다는 뜻.
- H1은 cand_000·cand_004 모두 0/3(missed_evidence+wrong_answer): 심결 불복 소송 조문(심결 취소소송 규정)이 검색되지 않고 엉뚱한 조문(제189조)을 인용. 절 분해가 "심결에도 불복하면"을 법률 용어 "심결 취소소송, 법원"으로 바꾸지 못함.
- H13(보정 시기·범위)은 missing_fact 3/3: 보정 시기 항목 사실이 답에 안 들어감.

## 가설
1. prefetch 자료 각 청크 위에 코드가 청크 안의 조문 번호 목록("포함 조문: 제90조, …")을 붙이고, 지시문에 "모든 사실 문장 끝에 (제N조제N항) 형식으로 인용"을 명시하면 wrong_answer 회귀가 사라진다(cand_000의 조문 인용 습관 복원 + 정확한 번호 제공).
2. 법률 절차 용어 → 법률 검색어 확장표(코드, 일반 도메인 지식)로 "심결·불복·보정·정정·무효·통상실시권" 같은 용어가 질문에 있으면 보조 검색어를 추가해 H1·H13류의 누락 요소를 보강한다. 특정 질문 문장은 쓰지 않고 용어 단위만 쓴다.
3. 답이 짧고 조문 번호를 포함하도록 "7문장 이내" 대신 "6문장 이내"로 하고, 사전 자료로 요소가 모두 확인돼도 필요 시 추가 검색은 허용.

## 바꾼 구조
- cand_004 코드 복사 후: (a) `PREFETCH_NOTE` 재작성(인용 형식 강제, 근거 줄 규칙 유지), (b) `article_labels()`로 청크별 조문 번호 라벨을 doc 앞에 부착, (c) `EXPANSIONS` 용어표로 추가 검색(최대 2개)을 prefetch에 합침, (d) 절 1개여도 확장 용어가 있으면 prefetch 수행, (e) 사전 청크 상한 7→8.
- 시스템 프롬프트·도구·send_email·승인·상한·finish·트레이스는 Step5 상속 그대로. 메일 요청 질문은 prefetch 제외(안전).
